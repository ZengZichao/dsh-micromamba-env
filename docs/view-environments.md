# 查看本机的 micromamba 环境

打开面板一次，就能看到每个环境的名称、绝对路径、状态标签、包数量和解释器版本。

1. 点击侧边栏的 **Micromamba**。
2. 在标题行下方读取 `micromamba <版本号>`，确认插件正在用的是哪一份二进制。
3. 逐个环境行读第一行：环境名，以及 **默认**、**当前**、**外部** 三个标签中命中的那几个。
   > 提示：三个标签的含义不同，别混着理解。[三个标签与只读边界](./concepts.md) 里有逐条定义。
4. 读第二行的绝对路径。
5. 读第三行的 `Python 3.11.9`、`R 4.3.3`、`480 个软件包`；某项缺失就不显示。
6. 需要最新结果时，点标题行右侧的 **刷新**。
   > 提示：**刷新** 是图标按钮，悬停才显示文字提示。它会绕过 30 秒的列表缓存，并清掉已展开的包列表缓存。

**结果：** 每个环境三段信息齐全——名称加标签、路径、解释器与包数；标题行下方显示版本号。

面板顶部如果出现 **工作区** 和 **环境** 两栏，说明当前有打开的会话：前者是会话所在工作区的文件夹名，后者是这个工作区已选的环境，没选时显示 **未选择**。

> 截图位：环境列表整体，至少包含一个带 **默认** 标签的行、一个带 **当前** 标签的行、一个带 **外部** 标签的行。alt：Micromamba 环境面板，三行环境分别带默认、当前、外部标签，每行下方是绝对路径和包数量。

## 读包数这一栏时要注意

- 显示 `—` 且没有红字：这个环境超出了 `maxDetailEnvs`（默认 25），插件没为它统计包数。
- 显示 `—` 并带红字 **读取失败：…**：这个环境的 `micromamba list` 失败了，环境本身可能损坏。修法见 [故障排除](./troubleshooting.md#某个环境的包数是破折号或读取失败)。
- 整块面板只有 **未找到环境。**：说明 `micromamba env list` 没有返回任何环境，通常是根前缀不对。
